# `libaocstats` — Character & NPC Stat Formula Bytecode Engine

`libaocstats` (`aocstats`) is a self-contained C++23 static library that parses, verifies, and executes the compiled stat and ability expression bytecode bundle (`AOSP` format version 3) generated by [`src/server/services/internal/statprog`](../../server/services/internal/statprog/README.md) and stored in `dist/content/content.db` (`stat_program` table). It has zero dependencies on `world` networking or session state and guarantees bit-for-bit IEEE-754 parity with the Go `statprog` interpreter.

---

## 1. Core API & Bytecode Execution (`stats/stat_engine.h`)

```cpp
#include "stats/stat_engine.h"
using namespace aoc::world::stats;

StatBundle bundle;
std::string err;
if (!parse_bundle(bytes, bundle, err)) {
    // Rejects malformed headers, CRC mismatches, out-of-bounds tables, or cyclic orders
}

StatInputs in;
in.class_enum = 2;                   // ECharacterClass: Ranger 1, Bard 2, Cleric 3, Fighter 4,
                                     //                  Rogue 5, Summoner 6, Tank 7, Mage 8
in.level = 1;                        // 1..255
in.mods = {{stat_guid, 20.0}};       // Summed equipment stat block & set bonus contributions
in.equipped = {{"Secondary", "Item.Gear.Weapon.Shield"}}; // Equipped item gameplay tags by slot

StatResult out;
if (run_stats(bundle, in, StatState{}, out, err)) {
    for (const StatOut& s : out.stats) {
        // s.guid, s.replication (0 None, 1 Owner, 5 OwnerProxy, 6 ProxyOnly, 7 EveryoneProxy),
        // s.value, s.base, s.equip, s.regen
    }
}
```

### Verification & Execution Guarantees

- **Static Bundle Verification (`parse_bundle`)**: Validates the 16-byte `AOSP` header (`kBundleVersion = 3`), IEEE CRC-32 body checksum, constant/string/reference/curve/program table bounds, forward-only jump targets landing on instruction boundaries, deterministic stack height (`0..64`) on every control-flow path ending in a single `RET`, and a complete acyclic topological evaluation order (`Bundle.Order`) where every stat's initial value and final value are settled before any dependent formula reads them. It also verifies that `StatBundle::exprs` indices are strictly increasing and that no stat-graph formula invokes a host operation.
- **Bounded Execution (`run_stats`)**: Executes at most one instruction per bytecode byte and enforces a hard per-run instruction ceiling of `kMaxRunInstructions = 4,194,304` (evaluating the full character stat graph requires ~3,000 instructions). Runtime division by zero, curve evaluation at `NaN` or within an unsupported cubic segment, or non-finite results yield `0.0` and increment `StatResult::faults`.
- **State Interface (`StatState`)**: Supplies contextual inputs for combat, movement, unkillable flags, profession levels (defaulting to level 1 across all 22 professions), consumed item stats, and NPC `NpcShape` parameters (elite rank and 8-stat distribution weights for NPC profile classes `>= 32`).
- **IEEE-754 Float32 Boundary Rounding (`Mode::Float32`)**: Executes stack instructions in IEEE-754 `double` while rounding each formula return value, stat initial value, and final stat value to `float32` (`rnd32(x) = double(float(x))`), matching the retail client's formula precision (`442/442` exact float32 stats on the captured level-1 Bard). `Mode::Double` and `Mode::Single` are also supported by the format.

## 2. Gear Interpolation & Character Stat Deltas (`stats/gear.h`, `stats/character_stats.h`)

### Equipment Aggregation (`gear_inputs`)

`gear_inputs(catalog, worn, rounding)` computes `StatInputs::mods` and `StatInputs::equipped` from a character's worn items (`record`, `Quality`, `EEquipSlot`) over the `GearCatalog` interface (`content::ContentGearCatalog` backed by `content.db`):

1. **Rarity Band Interpolation**: Looks up each item's `QualityCurve` band (`Common 1..5` through `Artifact 101..200`) and interpolates each `ItemStatBlock` entry via `Min + (Max - Min) * (q - X) / (Y - X)`. Items without a curve use `CommonMin`.
2. **Rounding**: Applies `Rounding::HalfUp` to interpolated item stat values, except for percentage-displayed stats (`StatTypeDef.bDisplayAsPercentage` / `stat_def.display_pct = 1`), which remain unrounded fractional values (such as `MoveSpeedMult`, `CrateLootPercent`, and fishing hook rates).
3. **Set Bonuses & Slot Tags**: Sums active `SetBonus` tiers up to the worn piece count evaluated at the lowest rarity among worn pieces in that set, and maps each worn item's `GameplayTags` under its `EEquipSlot` name for `EquippedItemInSlotHasTag` queries.

### Live Stat Delta Tracking (`CharacterStats`)

`CharacterStats` maintains a player's replicated `float32` stat state across session join and equipment/effect updates:

- **`start(worn)`**: Initializes all class stats at session join. Stats flagged as `Reset_SetMax` (`Health`, `Mana`, `Stamina`, and class resources where `StatValue::held()` is true) initialize their current value to the computed maximum.
- **`prepare(worn, changed, next)` / `update(worn, changed)`**: Re-evaluates the stat graph after gear, passive, rank, or effect changes and populates `changed` with stats whose wire `float32` bit pattern changed (`+0.0` and `-0.0` are compared by raw bits; `NaN` equals itself), plus `base` and `equip` deltas for stats flagged to replicate breakdown values (`Artisan_Gathering_Fishing_Sport_*`). Current pool values (`Health`, `Mana`, `Stamina`) are preserved across updates and clamped only when the new maximum drops below the current value (`set_current` updates pool values during combat or ability spending). If `next.faults != 0`, the session rejects the update without mutating live pawn state.
- **Held Resources (`kStatResource`)**: `StatOut` exports `min`, `max`, and `regen` bounds for class resources (`content::kResourceStats`), and `StatInputs::current` feeds the held value back into `GetStat` reads.

## 3. Effect Modifiers, Ability Expressions & Host Functions

```cpp
in.effects = {{effect_ref, /*stacks=*/2, /*tags=*/{"Debuff.Staggered"}, /*mods=*/{{stat_guid, 0.03}}}};
in.ranks = {{{kTypeSkillTree, tree_guid}, {kTypeSkill, skill_guid}}};
run_stats(bundle, in, state, out, err);

ExprEvaluator ev(bundle, in, state, out);
SplitMix rng{seed};
double value = 0.0;
ev.eval(program_idx, host, value, err);
```

### Effect Stat Modifiers

Active effects (`StatInputs::effects`, bounded by `kMaxEffectStacks = 4096` and `kMaxActiveEffects = 4096`) apply after equipment contributions and before `ValueMin`/`ValueMax` clamps according to the target stat's `StatTypeDef` flags:

| Modifier Mode | Formula | `StatTypeDef` Flags | Examples |
|:---|:---|:---|:---|
| **Additive** | `value += mod * stacks` | `bMultiplyStatMods = 0` | `MoveSpeedMult`, `Evasion`, `MaxStamina` |
| **Multiplicative** | `value *= mod` (per stack) | `kStatMulMods` (`1`) | `HealingMult`, `DamageMult` |
| **Multiplicative Complement** | `value *= (1 - mod)` (per stack) | `kStatMulMods \| kStatMulCompl` (`1 \| 64`) | Mitigations and Penetrations (24 stats) |

### Expression Evaluator & Host Function IDs (`ExprEvaluator`, `ExprHost`)

`ExprEvaluator` executes compiled expression programs listed in `StatBundle::exprs` (ability costs, cooldowns, charges, cast times, hit/effect requirements, stat-mod formulas, loot predicates, city-node gates, and artisan equations) against a finished `StatResult`. Role-scoped reads (`caster`, `target`, `instigator`, `owner`) are bracketed by `OpActor` and bound via `ExprEvaluator::set_actor(role, view)`.

External game-state queries dispatch through `OpHost0`, `OpHost1`, and `OpHost2` (`0x61..0x63`) to `ExprHost::host_fn`:

| Host Function IDs | Header / Implementation | Functions Answered |
|:---|:---|:---|
| **`1..11`, `14`** | `stats/stat_engine.h` | `RemainingCharges` (`1`), `ApplicableTarget` (`2`), `MovementKey` (`3`), `StatDelta` (`4`), `HitStatMod` (`5`), `HitStatEffective` (`6`), `IsNeutral` (`7`), `IsEnemy` (`8`), `AngleBetween` (`9`), `Now` (`10`), `ProgressDuration` (`11`), `RandIntRange` (`14`, returns `lo` when `hi < lo`) |
| **`20..29`** | `stats/damage.h`, `stats/damage.cpp` | Native float32 combat damage functions over `DamageProfile`: `CalculateDamage`, `CalculateDamageMultiplier`, `CalculateDamageAdditiveMultiplier`, `CalculateDamageMitigation`, `CalculateDamageCritical`, `CalculateDamagePenetration`, `CalculateDamageDampening`, plus actor distance, identity, hit source type, and alignment relation queries |
| **`30..31`, `160..161`** | `stats/stat_engine.h` | Kill reward and loot table predicates: `GetPlayerLootMaxLevel` (`30`), `GetPlayerLootAvgLuck` (`31`), `DoesNPCContainTag` (`160`, case-insensitive `FName` tag match), `GetPlayerLevel` (`161`) |
| **`170..177`** | `src/server/world/world/city_nodes.h` (`node_host_fn`) | City node and Zone of Influence (ZOI) queries: `GetNodeBiome` (`170`), `GetCurrentNode` (`171`), `GetNodeRecord` (`172`), `Node_GetNodeType` (`173`), `Node_GetLevel` (`174`), `Node_InLevelRangeInclusive` (`175`), `Node_IsPlayerCitizen` (`176`), `Node_IsPlayerCitizenOfNode` / `Node_IsPlayerMayor` (`177`) |
| **`180..184`** | `stats/gather_host.h` (`gather_host_fn`) | Artisan harvesting and processing queries over `stats::GatherContext`: `GetArtisanshipModifiedStat` (`180`), `GetRolledItemQuality` (`181`), `GetItemRarity` (`182`), `GetSourceCertificationTier` (`183`), `GetGatheringInteractionBaseDuration` (`184`) |

### Ability Content Loader (`content/ability_content.h`)

`AbilityContent` (`world_ability_content`) loads the compiled `ab_*` ability, cost, montage (`net_guid`), hit, effect, modifier, projectile, lingering zone, and `ab_expr` tables from `dist/content/content.db`, providing `auto_ranks_at(level)` and compiled expression lookup (`expr(id)`) for the `world` ability pipeline.

## 4. Verification & Differential Corpus Suite

Run the C++ stat engine test suite via:

```powershell
pwsh -File sandal.ps1 test
```

The test executables in [`src/tests/cpp/`](../../tests/cpp/) verify `libaocstats` against the shared cross-language corpus (`build/gen/fixtures/corpus.txt`, generated and checked by `go run ./internal/statprog/cmd/statprog corpus --check`):

- **`test_world_stats`**:
  - Parses and verifies 5 reference bundles (production graph in `Float32` and `Double` modes, `TinyGraph` exercising every opcode and state query in `Float32` and `Single` modes, and an instruction-budget exhaustion bundle).
  - Verifies bit-for-bit output parity with Go across 38 character profiles (including `442/442` exact float32 stats on the captured level-1 Bard, the level-20 retail Ranger, all 8 classes' starting kits at levels 1 and 20, and NPC `DamageProfile` cases).
  - Rejects 98 hostile malformed bundles, all byte-by-byte truncations of the production and tiny bundles, and 28,000 seeded differential bit/byte-flip fuzz mutations with identical verdict counts and output hashes across Go and C++.
  - Exercises `gear_inputs` rarity interpolation, `Rounding::HalfUp`, set bonuses, and `CharacterStats` delta emission and pool clamping.
- **`test_world_effects`**:
  - Executes 14 `fxcase` suites (3,640 compiled expression evaluations across 507 production ability programs and `TinyGraph` edge cases, plus `gatherhost` and `nodehost` vectors) and verifies bit-identical results against Go, including retail mana costs, level-25 Bard Sprint (`MoveSpeedMult = 1.3`), `Bard_Glee` mitigation (`0.9362`), and `Bard_Note_Comedy` healing (`1.1576`).
- **`test_world_ability_content`**:
  - Validates `AbilityContent` table loading and expression evaluation against `dist/content/content.db`.
